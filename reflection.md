# Reflection

During development, the AI-generated implementation needed careful checking against the written queue rules. One important area to verify was barber preference: when reception calls the next customer for a particular barber, the system must skip customers who selected a different named barber and choose only the earliest eligible customer who selected that barber or “Any barber.” I noticed this by comparing the Reception Dashboard behaviour with the rules in `docs/03-flows-rules.md` and by trying a queue containing customers with different barber preferences. I refined the implementation so the selection checks the requested barber before assigning a customer. This showed me that AI-generated code can speed up development, but it is still necessary to test real scenarios, compare behaviour with requirements, and make corrections instead of assuming that a working-looking screen is correct.
